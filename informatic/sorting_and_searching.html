⏱ 빅오(Big-O) 표기법

정렬 알고리즘 탭과 함께 보면 더 쉬워요!

왼쪽 탭의 버블·선택·퀵 정렬을 바탕으로, "빅오"가 무엇이고 왜 중요한지 차근차근 알아봐요.

빅오 표기법, 왜 필요할까요?

빅오(Big-O) 표기법은 입력 데이터의 크기(n)가 커질 때, 알고리즘의 실행 시간이나 메모리 사용량이 얼마나 빠르게 늘어나는지를 나타내는 방법이에요. 컴퓨터 성능이나 실행 환경에 상관없이, "이 알고리즘은 대략 이 정도 속도로 느려진다"는 걸 비교할 수 있게 해줍니다.

자주 등장하는 빅오 표기

O(1) 상수 시간 — 입력 크기와 무관하게 항상 일정한 시간

O(n) 선형 시간 — 입력이 2배가 되면 시간도 2배

O(n log n) 선형 로그 시간 — n과 log n을 곱한 만큼 증가 (퀵 정렬의 평균)

O(n²) 제곱 시간 — 입력이 2배가 되면 시간은 4배 (버블·선택 정렬)

※ 빅오는 "최악의 경우 혹은 평균적으로 얼마나 늘어나는가"에 집중하며, 정확한 초 단위 시간이 아니라 증가하는 추세(경향)를 나타냅니다.

🔢 로그(log)가 뭔지 몰라도 괜찮아요

"log n"이라는 말이 어렵게 느껴진다면, 숫자 맞히기 게임을 떠올려 보세요.

예시: 1~100 사이 숫자 맞히기 게임

친구가 1부터 100 사이의 숫자를 하나 정했어요. 당신은 "더 큰가요? 더 작은가요?"라는 질문만으로 그 숫자를 맞혀야 합니다.

가장 똑똑한 방법은 매번 가운데 숫자를 물어보는 거예요. 그러면 한 번 물어볼 때마다 남은 후보가 절반으로 줄어듭니다.

25개2번 질문

12개3번 질문

1개7번 질문

100개였던 후보가 7번만 질문해도 1개로 줄어들죠? 이렇게 "몇 번을 반으로 나눠야 1이 되는가"를 세는 숫자가 바로 log입니다.

한 줄 정의

log₂ n = "n을 몇 번 반으로 나눠야 1이 남는가?" 를 뜻해요. 예를 들어 log₂100 ≈ 6.6 이므로, 약 7번이면 100개 중에서 정답을 찾을 수 있습니다.

왜 로그는 "빠르다"고 할까요?

숫자(n)가 아무리 커져도, 매번 절반씩 줄기 때문에 필요한 횟수는 아주 천천히 늘어나요.

후보 개수 (n)몇 번 질문해야 할까? (log₂n, 반올림)

1,00010번
1,000,00020번

후보가 10개에서 100만 개로, 10만 배나 늘어나도 질문 횟수는 4번에서 20번으로밖에 늘지 않아요. 이것이 "로그적으로 증가한다"는 뜻이에요.

정렬과의 연결고리

퀵 정렬도 이 숫자 맞히기 게임처럼, 기준값(피벗)을 기준으로 숫자들을 두 그룹(작은 그룹/큰 그룹)으로 절반씩 나누며 정렬합니다. 그래서 "n개를 몇 번 나눠야 끝나는가"를 나타내는 log n이 시간 복잡도에 등장하는 거예요. 거기에 각 단계마다 n개를 훑어봐야 하므로 전체는 n × log n, 즉 O(n log n)이 됩니다.

정렬 알고리즘과 연결해 보기

버블 정렬 — 이웃끼리 비교·교환을 반복 → 평균/최악 모두 O(n²)
선택 정렬 — 매번 최솟값을 찾아 앞으로 이동 → 평균/최악 모두 O(n²)
퀵 정렬 — 기준값으로 분할·정복(절반씩 나누기) → 평균 O(n log n), 최악 O(n²)
항목버블 정렬선택 정렬퀵 정렬
핵심 규칙이웃끼리 비교·교환최솟값 선택기준값으로 분할
평균 시간 복잡도O(n²)O(n²)O(n log n)
최악 시간 복잡도O(n²)O(n²)O(n²)

퀵 정렬도 기준값(피벗)을 계속 최솟값/최댓값으로 고르면 숫자 맞히기 게임에서 매번 "1 아니면 100입니다"라고 질문하는 것과 같아져요. 그룹이 절반씩 줄지 않고 한 개씩만 줄기 때문에, 최악의 경우 O(n²)까지 느려질 수 있습니다.
